Фактические результаты совпадают с ожидаемыми и корректно определяют уровень оценки.

#### Порядок проверки условий:
  ```
def classification(result, work_type, absences):
    if not (type(result) == int and 0 <= result <= 100 and type(absences) == int and 0 <= absences <= 5):
        return None

    level_id = get_level(result)
    level = adjust_level(absences, level_id)
    work = describe_work(work_type)
  ```
Сначала в функции `classification()` проверяется кооректность входных данных (диапазон значений и их тип), если он неверен, функция возвращает `None`, а потом функция `sumup()` сообщает пользователю о неверном вводе. Далее вызывается функция `get_level()`, которая возвращает id уровня обучения в зависимости от полученного балла. Затем в функцию `adjust_level()` передаются количество пропущенных занятий и id уровня, в ней он корректируется в зависимости от количества пропусков и возвращает результат в виде текстовой оценки. Последним проверяется тип работы в `describe_work()`.

Если введеные данные некорректны, то функция обрывается, ничего не проверяя, выводя "Input error".

### Практическое расширение
В первоначальный алгоритм была добавлена функция sumup(), которая проверяет все выводы функции classification() и выводит сводку по результатам студентов (сколько студентов каждой оценки). Пример вывода для таблицы выше:

## Задание 2. Циклы и базовые алгоритмические схемы 

### Дополнительный алгоритмический эксперимент

#### Временная сложность алгоритмов:
Проверка числа на простоту - сложность $O(\sqrt(x))$
Бинарный поиск - сложность $O(log n)$
Линейный поиск - сложность $O(n)$

#### От какого параметра зависит число операций?
Для алгоритмов обработки массива и линейного поиска число операций зависит от размера массива $n$. Для алгоритма проверки простоты числа количество операций зависит от величины самого проверяемого числа $x$.

#### Сколько дополнительной памяти требуется?
Всем реализованным алгоритмам требуется константный объем дополнительной памяти, то есть $O(1)$. Мы создаем фиксированное количество простых переменных (счетчики, минимумы, суммы), объем которых не увеличивается с ростом размера массива или проверяемого числа.

#### Почему ограничение делителей квадратным корнем корректно?
Потому что множители (если раскладывать на 2) обратно пропорциональны, таким образом макисмально равные множители будут лежать рядом с корнем, таким образом остальные произведения содежат 1 число большее корня и 1 меньшее, а так как все числа до корня мы перерали, то и меньшее число учитывалось, а значит и большее тоже (так как большее * меньшее = искомое).

## Задание 3. Коллекции и выбор структуры данных

#### Добавьте новую запись и обновите структуры без полного повторного построения. Объясните, почему:

#### Множество подходит для хранения уникальных значений;
Потому что множество хранит только уникальные элементы.

#### Кортеж можно использовать как ключ словаря;
Ключем в словаре может быть только неизменяемый объект, коим является кортеж.

#### Cписок нельзя использовать как ключ словаря;
Список - изменяемый объект, потэтому не может использоваться как ключ в словаре.

#### Cловарь предпочтительнее списка для частого поиска результата по составному ключу.
Потому что на значения в словаре мы сами можем назначить ссылки какие хотим (из неизменяемых объектов), в списке же ссылкой на элемент является только индекс, что может быть неудобно.
