Фактические результаты совпадают с ожидаемыми и корректно определяют уровень оценки.

#### Порядок проверки условий:
  ```
def classification(result, work_type, absences):
    if not (type(result) == int and 0 <= result <= 100 and type(absences) == int and 0 <= absences <= 5):
        return None

    level_id = get_level(result)
    level = adjust_level(absences, level_id)
    work = describe_work(work_type)
  ```
Сначала в функции `classification()` проверяется кооректность входных данных (диапазон значений и их тип), если он неверен, функция возвращает `None`, а потом функция `sumup()` сообщает пользователю о неверном вводе. Далее вызывается функция `get_level()`, которая возвращает id уровня обучения в зависимости от полученного балла. Затем в функцию `adjust_level()` передаются количество пропущенных занятий и id уровня, в ней он корректируется в зависимости от количества пропусков и возвращает результат в виде текстовой оценки. Последним проверяется тип работы в `describe_work()`.

Если введеные данные некорректны, то функция обрывается, ничего не проверяя, выводя "Input error".

### Практическое расширение
В первоначальный алгоритм была добавлена функция sumup(), которая проверяет все выводы функции classification() и выводит сводку по результатам студентов (сколько студентов каждой оценки). Пример вывода для таблицы выше:
```
Всего студентов: 10
Студентов каждого уровня:
недостаточный: 4
удовлетворительный: 4
хороший: 1
отличный: 1
```
